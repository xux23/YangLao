# 养老机构管理系统（Spring Boot + Vue 3）

面向中小型养老机构的信息化管理系统，覆盖**老人档案、护理管理、健康管理、探访管理、系统管理**五大模块，
支持管理员 / 护理人员 / 家属三类角色协同使用。

- 后端：Spring Boot 3.2 + MyBatis-Plus + MySQL 8.0 + JWT，**10 个 REST 控制器、46 个接口、8 张业务表**
- 前端：Vue 3 + Vite + Element Plus + Pinia + ECharts
- 测试：58 项接口回归断言脚本（`test_api.js`），覆盖三个角色的鉴权与越权场景

## 技术栈

| 层次 | 技术 |
|------|------|
| 后端 | Spring Boot 3.2、MyBatis-Plus、MySQL 8.0、JWT（jjwt）、EasyExcel、AOP、Lombok、Maven |
| 前端 | Vue 3、Vite、Element Plus、Vue Router、Pinia、Axios、ECharts |
| 环境 | JDK 17+、Node 16+、MySQL 8.0 |

## 功能模块

| 模块 | 主要功能 | 使用角色 |
|------|----------|----------|
| 系统管理 | 用户管理、操作日志、数据看板与统计图表、个人中心 | 管理员 |
| 老人档案 | 档案维护、入住 / 退住登记、房间床位分配、名单导出 | 管理员、护理人员 |
| 护理管理 | 护理计划与执行记录、记录导出 | 护理人员 |
| 健康管理 | 健康档案、体征数据、用药计划与每日用药任务闭环 | 护理人员维护 / 家属只读 |
| 探访管理 | 探访预约与审核、家属留言回复 | 家属提交 / 机构审核 |

## 设计要点

1. **接口级 + 数据级两层防护**：JWT（HS256，24h）无状态认证 + 自定义 `@RequireRole` 注解配合拦截器做接口鉴权，
   当前登录用户存于 ThreadLocal，业务层直接取用；密码 BCrypt 加盐存储。
2. **家属数据隔离**：家属查询健康 / 探访 / 留言时，服务端强制按 `elder_info.family_id` 过滤，
   直接访问其他老人 ID 返回 403。
3. **AOP 操作日志**：`@OperLog` 注解 + 切面统一记录操作人、接口、参数、IP，不侵入业务代码。
4. **用药任务闭环**：按需生成当日用药任务 → 确认执行 → 未执行次日自动标记逾期 → 支持补服确认；
   计划停用时以 `disabled` 标志位阻断任务延续（解决"删行后次日又重新生成"的设计冲突，见 `设计方案汇总.md` 第六节）。
5. **表设计取舍**：角色、房间床位、用药任务等小数据以字段承载，不额外拆表，减少联表复杂度。

## 快速开始

```bash
# 1. 初始化数据库（创建 elder_care 库、8 张表与演示数据）
mysql -u root -p < 需求/init.sql

# 2. 启动后端（默认 8080，数据库账号在 application.yml 中修改）
cd 养老机构管理系统/backend && mvn spring-boot:run

# 3. 启动前端（默认 8081，/api 已代理到后端）
cd 养老机构管理系统/frontend && npm install && npm run dev
```

演示账号：`admin` / `nurse01` / `family01`，密码均为 `123456`。详细演示路径见 `养老机构管理系统/README.md`。
