# 养老机构管理系统 · 代码阅读指南

> 本指南帮助你在答辩前读懂项目全部代码，从"看得懂"到"讲得出"。
> 建议配合 IDE（IDEA 打开 `backend`、VSCode 打开 `frontend`）边读边跳转。

---

## 一、整体认知：5 分钟看懂项目在做什么

系统是**前后端分离**的 B/S 架构，一句话概括数据流：

```
浏览器(Vue3) → Axios(带JWT令牌) → REST接口(Controller) → 业务逻辑(Service) → MyBatis-Plus(Mapper) → MySQL(8张表)
```

用户分三类，权限层层拦截：

| 角色 | 典型动作 | 代码中的体现 |
|------|---------|-------------|
| admin 管理员 | 全部功能 | 所有接口都放行 |
| nurse 护理人员 | 维护业务数据 | 接口标注 `@RequireRole({"admin","nurse"})` |
| family 家属 | 只读 + 提交预约/留言 | 接口标注 `@RequireRole("family")`，且只能操作"自己关联的老人" |

## 二、推荐阅读顺序（按答辩权重）

### 第 1 步：数据库（15 分钟）→ `sql/init.sql`

先看 8 张表，这是项目的"骨架"：

| 表 | 一句话理解 |
|----|-----------|
| sys_user | 三角色共用一张用户表，`role` 字段区分 |
| elder_info | 业务主表，房间/床位直接放字段（不建房间表） |
| care_record | 护理记录（计划与执行合一） |
| health_record | 体征记录（血压/心率/体温/血糖） |
| medicine_plan | 用药计划=任务（一行=某天某时间点一次服药） |
| visit_appointment | 探访预约与审核状态 |
| message | 家属留言与机构回复 |
| sys_log | 操作日志（AOP 自动写） |

**看的时候注意**：
- 状态字段全部是 TINYINT，约定在需求文档 5.2 节
- 没有物理外键，关联靠业务层保证（毕设惯例）
- `medicine_plan.disabled` 字段是设计亮点（下面第 5 节讲）

然后打开 `需求/需求分析文档.md` 的 4.2 节"用药任务闭环"，这是全项目**最核心的算法**。

### 第 2 步：后端入口（10 分钟）

按这个顺序读：

1. `backend/pom.xml` —— 用了哪些依赖（Spring Boot 3.2、MyBatis-Plus、jjwt、EasyExcel、Lombok）
2. `backend/src/main/resources/application.yml` —— 端口 8080、数据库连接、JWT 密钥配置
3. `EldercareApplication.java` —— 启动类
4. `common/Result.java` —— 统一响应体 `{code, message, data}`
5. `common/GlobalExceptionHandler.java` —— 全局异常处理器（业务异常转 JSON）

> **答辩点**：全局异常处理——Controller 里看不到 try-catch，业务校验只 `throw new BusinessException(403, "...")`，统一由这里转成 JSON 响应。

### 第 3 步：登录与鉴权链路（30 分钟，答辩必讲）→ `security/` 包

这是项目**最有技术含量**的部分，按调用顺序读：

```
AuthController.login → AuthServiceImpl.login
    → BCrypt 校验密码（spring-security-crypto）
    → JwtUtil.createToken(userId, username, role)  签发JWT，有效期24小时
前端保存 token → 之后每个请求带 Authorization: Bearer xxx
JwtInterceptor.preHandle（每个请求先进这里）
    → JwtUtil.parseToken 验证签名和过期时间
    → UserContext.set(user)    把用户放进 ThreadLocal
    → 检查方法上的 @RequireRole 注解 → 角色不在允许列表抛 403
afterCompletion → UserContext.clear()  清理，防止线程复用串号
```

**阅读要点**：
- `UserContext` 用 ThreadLocal 存当前登录用户——这是让 Service/AOP 层随时拿到"我是谁"的关键
- `JwtInterceptor` 注册在 `config/WebConfig.java`，放行 `/api/auth/login`
- `@RequireRole` 是自定义注解（`security/RequireRole.java`），Controller 方法上标注即可控权限

> **答辩点**：JWT 无状态认证——服务端不存会话，令牌自带身份信息；ThreadLocal 上下文传递当前用户。

### 第 4 步：跟一条完整业务流（30 分钟）→ 老人档案为例

以"管理员查老人列表"为例，在 IDE 里按调用链跳转：

```
ElderController.page (GET /api/elders)
    ↓ 调用
ElderService.pageElder
    ↓ 实现
ElderServiceImpl.pageElder
    → LambdaQueryWrapper 拼条件（name模糊、roomNo、status）
    → elderInfoMapper.selectPage  （MyBatis-Plus 分页插件）
    → fillFamilyNames 补充关联家属姓名（二次查询，非表字段）
    → 返回 Page<ElderInfo>
```

**阅读要点**：
- Controller 只做参数接收和返回，逻辑全在 Service
- `LambdaQueryWrapper` 是 MyBatis-Plus 的查询条件构造器，所有查询条件用 `.eq/.like` 拼接，**天然防 SQL 注入**（参数化）
- 实体类里的 `elderName`、`familyName` 等字段标注了 `@TableField(exist = false)`，表示"不是数据库字段，查询后手动填充"

**同理可读其他模块**：护理、体征、留言、探访的 Controller→Service→ServiceImpl 结构完全一样。

### 第 5 步：核心亮点逐个看（答辩重点，每个 15 分钟）

#### ① AOP 操作日志 → `aspect/LogAspect.java` + `aspect/OperLog.java`

```java
@OperLog("新增老人")   // Controller 方法上加这一行
public Result<Void> add(...) {...}
```

LogAspect 用 `@Around` 切面拦截：方法执行成功后，把操作人、操作描述、请求路径、参数（截断500字符）、IP 写入 sys_log 表。**业务代码零侵入**——写操作只需要加一个注解。

> **答辩点**：切面在目标方法成功执行后记录（`joinPoint.proceed()` 之后），操作失败不记录；日志记录失败也不影响业务（try-catch 兜底）。

#### ② 用药任务闭环 → `service/impl/MedicinePlanServiceImpl.java`（项目核心！）

对照需求文档 4.2 节的算法看这 5 个方法：

| 方法 | 作用 |
|------|------|
| `addPlan` | 录入计划：为当天每个时间点插入一行任务（status=0 待执行） |
| `listTasks` | **核心**：① 逾期扫描（过期未执行 → status=2）② 当天没任务则按"最近一天"复制生成 |
| `completeTask` | 确认执行：status=1 + 记录 confirm_time |
| `listOverdueTasks` | 逾期列表（查询前也先做一次逾期扫描） |
| `disablePlan` | 停用：删今天及以后任务行 + 历史行置 disabled=1 |

**设计精妙处（答辩必讲）**：
- **按需生成，不提前占库**：每天的任务不是定时任务生成的，而是"查询当天没有时"才从最近一天复制，天然延续服药方案
- **逾期扫描**：查询时顺手把过期任务标逾期，不依赖定时任务
- **disabled 字段**：停用如果只删行，次日按需生成又会从历史行复制出新任务（复活）。所以停用时把历史行置 disabled=1，生成逻辑见到停用行就停止延续。

#### ③ 家属数据隔离 → `ElderServiceImpl.checkFamilyOwnership`

家属角色访问老人数据前，先查 `elder_info.family_id` 是否等于当前登录用户 ID，不等则抛 403。探访、留言、体征列表同理强制拼接归属条件。

> **答辩点**：接口级鉴权（@RequireRole）挡的是"角色不对"；数据级隔离挡的是"角色对但访问了别人的数据"（水平越权）。两层防线。

#### ④ Excel 导出 → `ElderController.export` + `vo/ElderExportVO.java`

EasyExcel 三步：设置响应头 → `EasyExcel.write(输出流, 导出VO.class)` → `doWrite(数据)`。导出VO 用 `@ExcelProperty("列名")` 定义表头。前端用 `responseType:'blob'` 接收触发下载。

#### ⑤ 统计看板 → `StatsServiceImpl` + `mapper/StatsMapper.java`

看板数据全是聚合 SQL（`@Select` 注解写在 Mapper 接口上）：
- 入住率：`COUNT(status=1)/COUNT(*)`
- 年龄分布：`CASE WHEN TIMESTAMPDIFF(...)` 分区间 GROUP BY
- 趋势：按天 GROUP BY，无数据日期前端补 0
- 体征趋势：按日期取记录，血压字符串前端拆成收缩压/舒张压两条线

### 第 6 步：前端（60 分钟）→ `frontend/src/`

按这个顺序读：

```
1. main.js          入口：注册 Pinia、Router、Element Plus、全局图标，引入全局主题
2. styles/theme.css 全局主题"暖阳关怀"：覆盖 Element Plus CSS 变量，全站换肤
3. router/index.js  路由表 + 路由守卫（meta.roles 控制谁能访问）
4. store/user.js    Pinia 登录态（token + user，存 localStorage）
5. utils/request.js Axios 封装：请求自动带 token，响应统一处理 401/403/错误
6. views/layout/Layout.vue  主框架：米色菜单（按角色过滤）+ 顶栏（改密码/退出）
7. 挑一个页面读透：views/elder/ElderList.vue
8. api/elder.js    接口封装（一个文件对应一个模块）
```

> **答辩点**：全局主题通过覆盖 Element Plus 的 CSS 变量（`--el-color-primary` 等）实现——`theme.css` 一处定义配色/圆角/胶囊标签，全站组件自动换肤，不侵入任何业务代码；标题用宋体系衬线字体，形成区别于默认后台模板的"暖阳关怀"视觉风格（奶油底 + 柿橙主色 + 墨绿辅助）。

**以 ElderList.vue 为例的阅读路径**：
- `<el-table :data="tableData">` 表格 → `loadData()` 调 `getElders(query)` → `api/elder.js` → `request.get('/elders')` → 后端
- 弹窗表单：`openDialog()` 打开 `el-dialog` → `handleSave()` 调 `addElder/updateElder`
- 分页：`el-pagination` 绑定 `query.page/size`，翻页重新 `loadData()`

**前端三个常用套路**：
- 列表页 = 查询表单 + el-table + el-pagination，所有列表页都是一个模板
- 弹窗表单 = el-dialog + el-form + 校验 rules + 保存调接口
- 导出 = 调接口（responseType blob）→ request.js 里的 `downloadFile()` 触发下载

**看板图表**（`views/dashboard/Dashboard.vue`）：`echarts.init` 初始化 → `setOption` 渲染 → 窗口 resize 自适应 → 组件销毁时 `dispose` 释放。

## 四、答辩高频问题 → 代码位置速查表

| 答辩问题 | 去读哪里 | 怎么答 |
|---------|---------|--------|
| JWT 怎么实现的？ | `security/JwtUtil.java` | 生成：payload 放 userId/username/role + 过期时间，HS256 签名；校验：解析签名 + 过期 |
| 权限怎么控制的？ | `JwtInterceptor` + `RequireRole` | 拦截器解析 token → 取出角色 → 比对方法注解允许的角色列表 |
| 操作日志怎么实现的？ | `aspect/LogAspect.java` | 自定义注解 + @Around 切面，成功后写库，零侵入 |
| 用药任务怎么自动生成的？ | `MedicinePlanServiceImpl.listTasks` | 查询当天没有 → 复制最近一天方案；同时做逾期扫描 |
| 停用计划为什么不会"复活"？ | `disablePlan` + `disabled` 字段 | 只删行会被按需生成逻辑复制回来，置 disabled 标记阻断 |
| 家属怎么能看到别人数据？ | `checkFamilyOwnership`、`getMyElderId` | 服务端强制拼接 family_id = 当前用户，越权返回 403 |
| Excel 怎么导出的？ | `ElderController.export` | EasyExcel 三步：响应头 + write + doWrite |
| 统一异常怎么处理的？ | `common/GlobalExceptionHandler` | @RestControllerAdvice 捕获 BusinessException/校验异常/其他异常 |
| 密码安全？ | `AuthServiceImpl` | BCrypt 加盐存储，登录时 matches 校验，接口不返回密码字段（@JsonIgnore） |
| 为什么不用 Redis 缓存？ | `application.yml` | 单机部署演示，无中间件，JWT 无状态已满足需求 |
| 表设计为什么房间不建表？ | `elder_info` 表结构 | 小数据用字段，减少联表复杂度（需求文档 5 章设计原则） |
